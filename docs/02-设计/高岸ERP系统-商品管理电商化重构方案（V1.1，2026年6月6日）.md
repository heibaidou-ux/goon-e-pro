## 一、重构目标与范围

### 1.1 目标

对ERP后台商品管理模块及客人端小程序商品展示进行"电商化"重构，从当前以表单字段为主的商品管理模式，升级为**以视觉内容为核心、移动端优先、小程序同步**的电商式商品管理体系。

### 1.2 范围

| 模块 | 覆盖范围 | 优先级 |
|------|---------|--------|
| ERP后台 - 商品新增/编辑 | 图片上传组件（拖拽+粘贴）、规格管理、头图设置、商品故事内容编辑 | P0 |
| ERP后台 - 商品列表 | 缩略图列表视图、批量图片管理 | P0 |
| ERP后台 - 图片资源管理 | CDN同步、缩略图自动生成、图片裁剪与排序 | P0 |
| 客人端小程序 - 零售页 | 高清缩略图列表、分类瀑布流 | P0 |
| 客人端小程序 - 商品详情页 | 头图轮播+信息卡片+故事内容（冲泡建议、产地等） | P0 |

### 1.3 不覆盖范围

- 商品目录审批流程（已有F24泳道图，本方案不修改）
- 商品价格体系（由§3.2动态价格体系管控）
- 物联网设备与商品的关联（留待后续版本）

## 二、商品图片存储架构

### 2.1 整体架构

```
┌──────────────────────────────────────────────────────────┐
│                     ERP后台（Web）                         │
│  商品新增/编辑页面 → 图片上传组件（拖拽/粘贴/选择文件）       │
└───────────────────────┬──────────────────────────────────┘
                        │
                        ▼
┌──────────────────────────────────────────────────────────┐
│                图片处理服务（后端）                          │
│  1. 接收原始图片 → 校验格式/大小                           │
│  2. 生成多尺寸缩略图（240px / 480px / 800px / 原始）       │
│  3. 自动裁剪头图（16:9, 1:1）                              │
│  4. WebP格式转换（降级JPEG）                               │
└───────────────────────┬──────────────────────────────────┘
                        │
                        ▼
┌──────────────────────────────────────────────────────────┐
│                  对象存储服务（OSS/S3）                    │
│  桶结构：                                                │
│  /products/{productId}/                                   │
│    ├── original/    ← 原始文件存档                         │
│    ├── thumbnail/   ← 240px缩略图（列表用）                │
│    ├── medium/      ← 480px中图（分类浏览用）              │
│    └── large/       ← 800px大图（详情页轮播用）            │
└───────────────────────┬──────────────────────────────────┘
                        │
                        ▼
┌──────────────────────────────────────────────────────────┐
│                  CDN分发（阿里云CDN/CloudFront）           │
│  边缘节点缓存图片，加速小程序加载                           │
└──────────────────────────────────────────────────────────┘
```

### 2.2 存储桶命名规则

```
bucket: erp-products
路径: /{tenant_id}/{category_code}/{product_id}/{size}_{index}.{fmt}

示例: /root/tea/PRD001/thumbnail_01.webp
      /root/tea/PRD001/large_01.webp
```

### 2.3 缩略图规格表

| 用途 | 尺寸 | 格式 | 质量 | 命名后缀 | 说明 |
|------|------|------|------|---------|------|
| 后台列表缩略图 | 240×240 (1:1裁切) | WebP（降级JPEG） | 80% | `thumbnail` | 列表行显示 |
| 小程序分类图 | 480×480 (1:1裁切) | WebP（降级JPEG） | 85% | `medium` | 分类瀑布流 |
| 详情页轮播图 | 800×自适应 | WebP（降级JPEG） | 90% | `large` | 详情页浏览 |
| 头图（宽版） | 1200×675 (16:9裁切) | WebP（降级JPEG） | 95% | `hero` | 详情页顶部 |
| 原始文件 | 原尺寸 | 原格式 | 100% | `original` | 存档，仅供重新生成缩略图 |

### 2.4 CDN缓存策略

| 资源类型 | 边缘缓存TTL | 浏览器缓存TTL | 说明 |
|---------|-----------|-------------|------|
| 缩略图（thumbnail/medium） | 30天 | 7天 | 文件名含MD5指纹，更新时自动失效 |
| 详情图（large/hero） | 7天 | 1天 | 新品上架期可能需要快速更新 |
| 原始文件（original） | 不缓存 | 不缓存 | 仅后台管理访问 |

## 三、ERP后台 - 图片上传组件

### 3.1 交互设计

#### 3.1.1 上传入口

位于商品新增/编辑表单的"商品图片"区域，提供三种上传方式：

| 上传方式 | 触发操作 | 适用场景 |
|---------|---------|---------|
| 点击选择 | 点击上传区域 → 文件选择对话框 | 常规上传 |
| 拖拽上传 | 从文件管理器拖拽图片到上传区域 | 批量操作 |
| 粘贴上传 | Ctrl+V / Cmd+V 粘贴剪贴板截图 | 快速截图上传 |

#### 3.1.3 上传中/上传后状态

| 状态 | 显示效果 | 说明 |
|------|---------|------|
| 上传中 | 缩略图灰化 + 进度条 | 显示上传进度百分比 |
| 上传成功 | 缩略图正常显示 + 成功标记 | — |
| 上传失败 | 缩略图红框 + 重试按钮 | 点击重试或移除 |

| 超限错误 | 错误提示Toast | 超过10MB时提示 |

### 3.2 图片编辑功能

| 功能 | 操作方式 | 说明 |
|------|---------|------|
| 设为头图 | 点击图片左上角⭐标记 | 第一张图默认头图，可更换 |
| 排序拖动 | 拖拽缩略图调整顺序 | 影响详情页轮播顺序 |
| 删除 | 悬停出现×按钮，点击删除 | 二次确认"确认删除此图片？" |
| 查看原图 | 点击缩略图打开大图预览Lightbox | 支持左右切换 |

#### 图片管理API

```
GET    /api/v1/products/{id}/images          — 获取商品图片列表

```

从现有"单一规格"升级为"多规格组"模型：

```json
{
  "productId": "PRD001",
  "specGroups": [

      "groupName": "包装",
      "type": "单选",
      "required": true,
      "items": [
        {
          "specValue": "袋装",
          "barcode": "6901234567890",
          "retailPrice": 88.00,
          "settlePrice": 60.00,
          "stock": 100,
          "isDefault": true
        },
        {
          "specValue": "罐装",
          "barcode": "6901234567891",
          "retailPrice": 268.00,
          "settlePrice": 180.00,
          "stock": 50,
          "isDefault": false
        },
        {
          "specValue": "礼盒装",
          "barcode": "6901234567892",
          "retailPrice": 588.00,
          "settlePrice": 400.00,
          "stock": 20,
          "isDefault": false
        }
      ]
    }
  ]
}
```

#### 规格管理业务规则

- 一个商品可定义多组规格（如：包装×年份），每组独立
- 是否启用规格管理由商品分类决定：
  - 茶叶类：默认启用（袋装/罐装/礼盒装为模板）
  - 茶具类：可选（如不同容量）
  - 茶点类：可选（如不同口味组合）
  - 套餐类：无需规格（固定组合）
- 启用规格后，库存管理精确到"规格级"而非"商品级"
- 规格条码支持扫码入库、出库

### 6.2 CDN刷新策略

| 触发场景 | 操作 | 说明 |
|---------|------|------|
| 商品图片新增 | 自动刷新该商品目录下CDN缓存 | 确保新图立即可见 |
| 商品图片删除 | 自动刷新该图片所有尺寸的CDN缓存 | 防止残图缓存 |
| 商品头图更换 | 自动刷新头图CDN缓存 | — |
| 商品信息更新 | 仅刷新详情页CDN缓存（非图片缓存） | 文本内容可直接更新 |
| 批量操作 | 支持手动全量刷新（后台按钮） | 运营工具 |

### 6.3 图片处理容错

| 异常场景 | 处理方案 |
|---------|---------|
| 图片处理服务临时不可用 | 原图直接存储，缩略图延迟异步生成，商品仍可发布（使用原图降级） |
| OSS上传失败 | 重试3次，间隔2秒，全部失败则标记图片状态为"处理失败"，提示用户重试 |
| CDN刷新失败 | 记录刷新队列，定时重试（每5分钟扫描失败记录） |
| 图片格式转换失败 | 使用原格式作为降级方案，记录处理日志 |

## 十一、扫码消费链路设计

### 11.1 业务目标与场景

#### 11.1.1 业务目标

实现客人**扫码即消费**的闭环体验，消除"到店后需手动搜索/选择房间"的摩擦，打通**线下流量→线上消费→自动挂账→月结合并**的全链路。

#### 11.1.2 适用场景

| 场景 | 说明 | 优先级 |
|------|------|--------|
| **到店落座扫码** | 客人进入已预约包间/桌位后，扫描桌上二维码，自动识别房号、跳转至商品点购页 | P0 |
| **到店无预约扫码** | 散客到店扫描空房/等位区二维码，提示"请联系店员开房"并引导至前台 | P0 |
| **加购扫码** | 客人在使用房间期间，再次扫码补充点单（茶点、商品等），自动挂入当前账单 | P0 |
| **外卖自提扫码** | 客人到店后在自提区扫描取餐码，自动核销并通知店员备餐 | P1 |
| **桌位多桌扫码** | 大型包间含多个茶桌，各桌独立扫码、统一挂入同一房间账单 | P1 |

### 11.2 QR码生成与管理

#### 11.2.1 码类型定义

| 码类型 | 编码规则 | 产生方式 | 使用场景 |
|--------|---------|---------|---------|
| **房间码** | 每房间唯一，固定码 | ERP后台手动生成/批量打印 | 包间门上/桌面上 |
| **桌位码** | 房间内每桌唯一（可选） | ERP后台生成，关联房间 | 大型包间多茶桌 |
| **取餐码** | 按订单动态生成，一次性 | 下单后自动生成 | 自提核销 |
| **门禁码** | 按房间+时段动态生成 | 预约成功/入住后自动下发 | 智能门锁开门 |

#### 11.2.2 房间码生成器 — ERP后台功能

**入口**：ERP后台 → 门店管理 → 房间管理 → 「生成房间码」按钮

**操作流程**：

```
房间管理列表
┌──────┬────────┬────────┬────────┬──────────┬──────────────┐
│ 房号  │ 房间名  │ 类型    │ 状态    │ 当前订单  │ 操作          │
├──────┼────────┼────────┼────────┼──────────┼──────────────┤
│ 888  │ 大茶室  │ 包间    │ 使用中  │ ORD-001  │ [编辑] [生成码]│
│ 889  │ 中茶室  │ 包间    │ 空闲    │ —        │ [编辑] [生成码]│
│ 890  │ 小茶室  │ 包间    │ 空闲    │ —        │ [编辑] [生成码]│
└──────┴────────┴────────┴────────┴──────────┴──────────────┘
                                                  │
                                          [批量生成]│  ← 支持多选批量生成/打印
                                                  ▼
                                    ┌─────────────────────────┐
                                    │ QR码预览与打印           │
                                    │ ┌───────────────────┐  │
                                    │ │   二维码          │  │
                                    │ │   (SVG/PNG)      │  │
                                    │ │                   │  │
                                    │ │ 大茶室 · 房号888  │  │
                                    │ │ 扫码点单/加购     │  │
                                    │ └───────────────────┘  │
                                    │                        │
                                    │ [下载PNG] [下载SVG]     │
                                    │ [批量打印] [复制链接]   │
                                    └─────────────────────────┘
```

**生成逻辑**：

- 首次生成：系统为该房间创建唯一 `roomCode`（格式：`GA-{门店编码}-{房间号}`），并生成对应二维码
- 重新生成：房间码更换时历史码自动失效，但保留变更记录以备追溯
- 批量打印：支持选择多房间 → 生成一页多码PDF → 直接打印裁切

#### 11.2.3 二维码参数协议

```
详细格式：
gaoan://scan?room_id=R888&store_id=S001&table_id=T1&t=1700000000

参数说明：
┌──────────┬────────┬────────┬──────────────────────────────────┐
│ 参数      │ 必填    │ 示例    │ 说明                             │
├──────────┼────────┼────────┼──────────────────────────────────┤
│ room_id  │ 是      │ R888   │ 房间ID（系统内唯一标识）           │
│ store_id │ 是      │ S001   │ 门店ID（多店路由）                │
│ table_id │ 否      │ T1     │ 桌位ID（大型包间分桌时使用）       │
│ t        │ 否      │ 1700…  │ 生成时间戳（用于校验码时效性）      │
│ sig      │ 否      │ abc…   │ 防伪签名（HMAC-SHA256，防止码被篡改）│
└──────────┴────────┴────────┴──────────────────────────────────┘

小程序落地页路由：
/pages/scan/landing?room_id=R888&store_id=S001
```

#### 11.2.4 二维码物理规范

| 项目 | 规格 | 说明 |
|------|------|------|
| 尺寸 | 40mm × 40mm | 桌上立牌 / 门贴 |
| 材质 | 亚克力透明立牌（桌面） / PVC防水贴纸（门） | 防油防水，日清洁不褪色 |
| 设计 | 中央二维码 + 下方"扫码点单"文字 + 房间名 | 白底黑码，品牌色边框 |
| 放置 | 桌面靠墙侧立牌；门外右侧门贴 | 客人入座后自然可见 |
| 备用量 | 每房间2份（桌面+门），门店总备用量20% | 损坏/脏污时即时替换 |

### 11.3 扫码落客验证（防误扫）

#### 11.3.1 验证流程

```
客人扫码
    │
    ▼
小程序扫码落地页
    │
    ▼
调用 GET /api/scan/room/{room_id}
    │
    ├── 房间不存在？ → 提示"二维码无效，请联系店员"
    │
    ├── 房间状态非Active？ → 提示"该房间当前不可使用，请联系店员"
    │
    ├── 无进行中的订单（空闲）？
    │   └── 提示"该房间暂无进行中的订单，请联系店员开房后再扫码点单"
    │       └── 提供 [联系店员] 按钮 → 唤起企业微信/电话
    │
    └── 有进行中的订单（InUse/PendingUse）？
        └── ✅ 验证通过 → 进入扫码加购页
            │
            ├── 显示欢迎语："欢迎使用 大茶室 · 房号888"
            ├── 显示当前订单号、已消费金额摘要
            └── 提供 [点单加购] [查看账单] 两个入口
```

#### 11.3.2 防误扫规则

| 规则 | 说明 |
|------|------|
| 房间状态验证 | 仅 `status=Active` 的房间可通过验证 |
| 订单存在性验证 | 必须有 `orderType=Room` 且 `status=InUse/PendingUse` 的订单 |
| 重复扫码 | 同一房间同一订单，多次扫码直接进入加购页（跳过验证） |
| 跨店扫码 | 若扫码门店与当前小程序登录门店不一致，提示切换门店 |
| 时间校验 | 二维码含 `t` 时间戳参数，超过30天未更新的码提示联系店员更换 |
| 防伪造 | 含HMAC签名的码被篡改后直接拒绝，记录异常日志 |

### 11.4 扫码点单与挂账

#### 11.4.1 加购流程


#### 11.4.2 挂账模型

扫码点单的核心机制是**挂账**（Tab/Open Bill）—— 订单金额不立即支付，而是累加到房间的实时账单中，待离店时统一结算。

```
房间订单 (Order, type=Room, status=InUse)
│
├── 房费：¥888（预付/已付）
│
└── 挂账子项（通过 roomId 关联的 Retail 订单）
    ├── Order#SCAN20260601001  ¥176  [扫码加购 - 已挂账]
    ├── Order#SCAN20260601002  ¥388  [扫码加购 - 已挂账]
    ├── Order#SCAN20260601003  ¥ 88  [扫码加购 - 已挂账]
    │
    └── 合计挂账：¥652
```

**挂账业务规则**：

| 规则 | 说明 |
|------|------|
| **挂账时效** | 自下单时起至房间订单结账时止，挂账期内不计利息、不额外收费 |
| **挂账上限** | 单房间挂账总额不超过该房间押金的2倍，超出时提示"请联系店员处理" |
| **挂账撤销** | 客人可在结账前自行撤销（取消订单），撤销后库存回滚 |
| **挂账转支付** | 房间结账时，挂账项可选一次性支付或部分支付 |
| **部分挂账** | 同一订单支持部分商品立即结算、部分挂账（如：商品立即付，茶食挂账） |

### 11.6 月结联动与对账

#### 11.6.1 扫码订单标签系统

扫码加购的订单通过 `tag` 字段自动标记，确保在月结/对账时与房费、其他零售订单清晰区分：

```json
{
  "orderId": "SCAN20260601001",
  "tags": ["扫码加购", "房间888", "挂账"],
  "tagMeta": {
    "sourceRoom": "R888",
    "sourceOrder": "ORD-001",
    "billStatus": "挂账中"   // 挂账中 / 已结算 / 已撤销
  }
}
```

#### 11.6.2 月结合并规则

| 场景 | 合并规则 | 会计分录 |
|------|---------|---------|
| **房费含消费套餐** | 扫码加购金额 ≥ 套餐含免额时，超出部分单独结算；含免额部分视为房费的一部分 | 房费收入：套餐价；加购超額：零售收入 |
| **房费不含消费** | 扫码加购全额单独结算，与房费分开开票 | 房费收入：房费；零售收入：扫码金额 |
| **预充值扣款** | 客人会员余额充足时，结账时自动扣除（房费+挂账合计） | 会员余额：减少；收入：房费+零售 |
| **混合支付** | 部分现金/微信支付 + 部分余额 | 按各支付方式拆分录入 |

**扫码订单对账标识**：

月结对账时，系统自动汇总所有 `tag="扫码加购"` 的订单，与房费合并生成对账单：

```
房间 888 · 月结对账单
═══════════════════════════
房费：      ¥888.00  (预付)
扫码加购：
  订单 SCAN20260601001  ¥176.00
  订单 SCAN20260601002  ¥388.00
  订单 SCAN20260601003  ¥ 88.00
扫码合计：  ¥652.00
───────────────────────────
应收总计：  ¥1,540.00
已收合计：  ¥888.00
待收：      ¥652.00
═══════════════════════════
```

#### 11.6.3 与现有结算体系的关系

| 结算维度 | 现有逻辑 | 扫码消费补充 |
|---------|---------|-------------|
| 订单类型 | Room（房费）/ Retail（零售） | Retail + tag=扫码加购，通过 roomId 关联房费订单 |
| 支付方式 | 微信/支付宝/余额/现金等 | 不变，挂账部分在离店结账时统一选择支付方式 |
| 对账维度 | 按订单逐笔对账 | 扫码订单按房间聚合后与房费合并对账 |
| 收入科目 | 房费收入 / 零售收入 | 不变，扫码加购归入零售收入，但标记来源为"扫码" |
| 发票开具 | 按订单开具 | 支持房费+扫码加购合并开具一张发票 |
